# Research-question evidence matrix

Evidence cutoff: 2026-07-18 (Europe/Berlin). This packet is a read-only
synthesis of the canonical 2A registries and the Wave 1/2 packets. It does not
add a numerical prior, make a routing decision, or validate a model alias.

## Interpretation rules

- **Supported mechanism** means an official interface or accounting rule is
  documented. It does not mean that a task-level effect size has been measured.
- **Qualitative only** means primary evidence illustrates a mechanism, but the
  sample, accounting, controls, or outcome linkage is insufficient for a routing
  prior.
- **Unanswerable** means the current registered corpus cannot identify the
  requested ranking, threshold, or causal effect. Unknown is not zero.
- Quality class A below applies only to official field semantics. No registered
  run currently qualifies as A-C evidence for numerical SmartRouter priors.

| How much token growth comes from repeated session history? | **Mechanism observable; magnitude unanswerable** | Agents SDK run usage, Codex turn usage, and app-server last-versus-total counters can capture aggregate growth by request/turn. | `OA-OFFICIAL-011`, `OA-OFFICIAL-012`, `OA-OFFICIAL-013`, `OA-OFFICIAL-014`, `OA-OFFICIAL-015` | These surfaces do not directly label which input tokens are re-sent history versus new prompt, tool result, or compaction content. | How does caching alter billed cost without changing total context processed? | **Supported mechanism** | Cached tokens remain input/context processing, are separately reported, use cache-specific dated pricing, and still count toward token-rate limits. | How does agent count change total tokens and pass rate? | **Qualitative only** | Primary multi-agent reports demonstrate that coordination/dialogue can add substantial input volume in bespoke systems. | `HWM-S027`, `HWM-S029`, `HWM-S031` | The examples change task, model, scaffold, and agent topology together. | Which measurements must SmartRouter collect locally? | **Strongly supported design requirement** | Exact model ID; request-level input/cache-write/cache-read/reasoning/output usage; component attribution; tool calls and payload burden; last versus cumulative use; context occupancy; compactions; retry/escalation chains; censored outcomes; verifier result; human review; timing; price/billing surface; agent attribution. | `OA-OFFICIAL-001`, `OA-OFFICIAL-007`, `OA-OFFICIAL-008`, `OA-OFFICIAL-011`, `OA-OFFICIAL-013`, `OA-OFFICIAL-014`, `OA-OFFICIAL-015` | No single official surface supplies the entire accepted-task record. Raw private transcripts are neither required nor safe to publish. | “Collect a privacy-minimized join across task, attempt, request, tool, verifier, and price records; preserve unknowns as null.” |

## Bottom line

The corpus supports a rigorous measurement design and several accounting
distinctions. It does **not** yet support a numerical ranking of token predictors,
failure predictors, or any Spark/Luna/Terra/Sol routing region. The honest 2A
result is a closed numerical-prior gate plus a specific local-measurement plan.
